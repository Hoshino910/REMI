# v0.3 current-truth DSH validation

This is the release gate for `v0.3.0-alpha.1`. Run it in a dedicated DSH session with a new SQLite filename. Do not reuse a v0.2 benchmark database.

## Configuration

Build the repository, mount `packages/dsh-adapter/dist/index.js`, and use unique paths for this run:

```yaml
currentTruthEnabled: true
transparentWindowEnabled: true
telemetryEnabled: true
databasePath: 'C:/path/to/test-data/remi-current-truth-alpha1.sqlite'
telemetryPath: 'C:/path/to/test-data/remi-current-truth-alpha1.jsonl'
```

Keep affect model analysis disabled for this test. It is unrelated to fact lifecycle behavior and would add extra provider calls.

## Conversation sequence

Send each message as a separate turn. Do not edit or regenerate earlier turns.

1. `For this test, reply only ACK to fact-write messages. The Cedar service port is 6389.`
2. `The Maple service port is 6389. Reply only ACK.`
3. `Change the Cedar service port from 6389 to 8247. Reply only ACK.`
4. `What is the current Cedar service port? Reply with only the number.`
5. `What is the current Maple service port? Reply with only the number.`
6. `What was the original Cedar service port and what is it now? Reply as OLD->CURRENT.`
7. `We may change the Cedar service port later. Reply only ACK.`
8. `What is the current Cedar service port? Reply with only the number.`
9. Run `/compact` once.
10. `What is the current Cedar service port after compaction? Reply with only the number.`
11. `What was the original Cedar service port and what is it now after compaction? Reply as OLD->CURRENT.`

Expected model-visible results are `8247`, `6389`, `6389->8247`, `8247`, `8247`, and `6389->8247` for steps 4, 5, 6, 8, 10, and 11 respectively.

## Persistence check

After step 11, stop DSH cleanly, start it again with the same plugin configuration and SQLite file, open the same session, and repeat steps 10 and 11. The answers must remain unchanged.

## Evidence checks

The run passes only when all of the following hold:

- The plugin starts without a duplicate compaction-provider error.
- One `memory/correction` event reports `resolution: "resolved"` for step 3.
- Step 7 does not produce a correction event and does not change the current value.
- The old Cedar record is `superseded`, has `valid_until`, and links to the active replacement.
- The Cedar replacement is `active` and links back through `supersedes_memory_id`.
- Maple remains active and unchanged.
- Ordinary current-value retrieval does not select the superseded Cedar record.
- Explicit history retrieval may select both versions, but `reinforcedEdges` does not include the superseded record.
- The same current/history behavior survives compaction and one DSH restart.
- Telemetry contains no raw port values or raw query text.

Any failed or ambiguous provider response is recorded as a model-output failure, not silently counted as a REMI lifecycle failure. SQLite state and telemetry determine whether the plugin path itself passed.
