# v0.3 long-context DSH validation

This note records a bounded live validation of REMI's retrieval window, native DSH compaction integration, and association telemetry. It is a mechanism check for `v0.3.0-alpha.1`, not a general model-quality or production-cost claim.

## Environment and isolation

- DSH Desktop 2.0.6.
- Compatibility baseline reported by the loaded plugin: `deepseek-ai/deepseek-harness@c291e796`, packages `0.1.5-rc.2`.
- Desktop compaction backend: `0.1.2-rc.1`.
- Dedicated DSH session, SQLite database, and telemetry stream.
- `currentTruthEnabled: false` so the run measured retrieval and compaction without lifecycle rewriting.
- Bounded per-session Hebbian graph enabled with a 2,048-edge cap.

The public evidence intentionally excludes local paths, access tokens, session identifiers, and raw conversation records.

## Protocol

1. Write two linked synthetic facts about the same deployment:
   - the manifest value;
   - the checkpoint signer.
2. Ask once for both values to prime a co-activation edge.
3. Send 96 independent interference turns. Each turn contains approximately 1,700 Chinese characters across unrelated topics and requests the exact response `ACK`.
4. Recall both initial facts before compaction.
5. Run native DSH `/compact`.
6. Recall the same facts after compaction.
7. Check the visible answers, SQLite state, `RetrievalTrace`, compaction trace, and graph counters independently.

The 96 interference turns contained 163,330 characters in total. All 96 returned `ACK`; the automation did not resend completed or slow turns.

## Results

| Check | Before compaction | After compaction |
| --- | ---: | ---: |
| Visible answer | Both fields correct | Both fields correct |
| DSH model-input usage shown for recall | 172K tokens | 11.6K tokens |
| Retrieval candidates | 198 | 200 |
| Selected memories | 2 | 2 |
| Estimated REMI injection | 132 tokens | 132 tokens |
| Retrieval duration | 48 ms | 51 ms |
| Association edges read/applied | 1 / 1 | 1 / 1 |
| Association-boosted candidates | 2 | 2 |

Both traces selected exactly the two original synthetic facts. None of the interference records entered the final memory window.

DSH reported that native compaction replaced 297 history records, approximately 78,696 tokens. REMI's compaction trace uses a different internal representation and recorded:

- 199 input entries;
- 87,394 estimated input tokens;
- 7 selected entries;
- 523 estimated output tokens under a 600-token budget;
- 5 ms compaction time.

These two entry counts are not directly comparable because DSH history records and REMI compaction entries have different boundaries.

The single stored association edge progressed from one to three co-activations across the priming, pre-compaction, and post-compaction recalls. Its final weight was approximately `0.100367`. Both recall traces reported positive association scores for the two selected memories.

The telemetry stream contained 101 retrieval traces, 202 ingested records, 99 memory-window events, one compaction event, and no REMI error event. The DSH UI briefly displayed one provider-side retry during a slow interference turn; the turn completed once, was not resent by the test driver, and the final saved retry state was empty.

## Interpretation and limits

This run demonstrates that the tested REMI build can recover two early facts after a 96-round interference sequence and again after native DSH compaction, while injecting a small bounded memory window. It also demonstrates that the stored Hebbian edge was read and affected scoring.

It does **not** establish that Hebbian scoring improves answer accuracy. A matched live `no_hebbian` control run is still required for a causal comparison. The run used synthetic English target facts, one configured model/provider path, and one DSH build. Hashed bag-of-tokens embeddings remain placeholders, token estimates are not billing measurements, and the plugin remains unsuitable for production use.
