## 最高价值缺口 1：用成对实验验证质量与总成本

实现/入口：

- `packages/benchmark/src/validation.ts`：冻结语料、严格 JSON 评分、disjoint token 计费、按 seed 聚类 bootstrap。
- `packages/benchmark/src/dsh-meter.ts`：所有组共同安装的 metadata-only `llm/stream` observer。
- `packages/benchmark/scripts/run-paired-validation.mjs`：一次执行一组、一个 seed、一次重复；两次压缩、held-out surface gate、失败不重发。
- `packages/benchmark/src/validation-cli.ts`、`examples/validation/local-config.example.json`。
- `packages/benchmark/tests/validation.test.ts`、`packages/benchmark/tests/meter.test.ts`。

可运行设计：先 `pnpm validate:offline`；随后按 `FRAMEWORK_V0.4.zh-CN.md` 在本地同一宿主模型配置运行 full / no_plugin / compaction_only / no_hebbian / no_affect。每个 seed 使用唯一 session；两组事实分别用于压缩前和压缩后召回，压缩后的 Orion 答案不在压缩前问题中泄露。各组输入顺序相同；no_plugin 保留完整历史，跳过 `/compact`；compaction_only 使用同一个 REMI extractive summarizer，仅禁用检索。另测宿主原生 basic compaction 时应单列第六组，不能冒充这里的 compaction_only。

输入例：`The Orion0 deployment seal is mark-255j. Reply only ACK.` → 24 轮干扰 → 两次 `/compact` → `What is the Orion0 deployment seal?`。期望精确输出 `{"value":"mark-255j"}`；未知实体期望 `{"value":null}`。模型应答格式不符计错，不事后放宽 scorer。

建议验收门槛（门槛不是结果）：每个主要 baseline 至少 30 个 seed × 3 次完整重复；完整 REMI 准确率 ≥95%，成对准确率差的 95% CI 下限 ≥−2 个百分点；平均总成本下降 ≥20% 且下降比例 95% CI 下限 >0。成本包括主调用、affect、压缩、标题和重试等辅助请求。价格卡须给来源、币种和生效时间；有缓存用量却无对应单价、缺模型调用、未完成 provider 对账、模型配置不一致、held-out surface 未过关，都只能输出 `insufficient-evidence`。

两个消融组仅用于衡量核心贡献，不是正常使用模式。完整配置的 Hebbian 与 affect 始终默认开启。模型 affect 的额外推理默认仍为可选，不能用“启发式 full”实验声称验证了“模型 affect”的收益。专门的 affect fixture 只证明评分会受 affect 影响与实体门槛仍生效，不能证明真实用户情绪理解。

## 最高价值缺口 2：跨 session 的事实生命周期不能串库或复活

实现/测试路径：`packages/core/src/types.ts`、`packages/core/src/runtime.ts`、`packages/store-sqlite/src/index.ts`、`packages/store-sqlite/tests/scope-lifecycle.test.ts`、`packages/dsh-adapter/src/correction.ts`、`packages/manager/src/index.ts`。

可运行命令：

```powershell
pnpm build
pnpm exec vitest run packages/store-sqlite/tests/scope-lifecycle.test.ts packages/dsh-adapter/tests/correction.test.ts packages/manager/tests/manager.test.ts
```

输入/输出场景：

1. A、B 绑定 `alice/cedar`；C 绑定 `bob/cedar`；D 绑定 `alice/maple`。A 写 `Cedar service port is 6389.`。B 默认 session 检索为空；B 显式 project 检索返回 A 的 6389；C、D 不可见。
2. B 用明确目标 ID 将端口改为 8247。当前检索仅有 8247；历史查询允许 6389 和 8247；旧记录 superseded，新记录 active，双向链接且一次事务提交。
3. 同项目再次启动 store、新 session 检索已建立的项目关联图，`associationEdgesRead > 0`、boosted candidates >0；外 owner/project 的读边数为 0。
4. 对修订链执行 delete。当前/历史/project 召回均无旧值，关联边归零；相同事件与相同正文的新 seq 重放均不能恢复；purge 后行内 content/embedding/affect/metadata 已清空。

量化门槛：隔离泄漏 0、错误实体更正 0、非 active 边强化 0、删除后精确重放复活 0；批次存在无权限/不存在 ID 时 100% 回滚；至少覆盖同 session、同项目跨 session、异 owner、异项目和重新打开数据库五种边界。扩展本机 E2E 应执行 3 次压缩、一次正常重启后重复全部断言。

本分支的删除是逻辑删除/行清理，不保证擦除 DSH durable log、SQLite 空闲页/WAL、provider 记录或备份。压缩只对精确 normalized 正文及 tombstone 指纹过滤；模型改写、含同一秘密的复合消息和宿主已有 checkpoint 仍可能保留内容。这些必须单列为 host-redaction / semantic-forgetting 的未完成工作，不能包装成已实现的彻底遗忘。跨项目绑定也不是用户登录鉴权。

## 最高价值缺口 3：透明窗口必须对应实际请求，并能解释两个核心的贡献

路径：`packages/dsh-adapter/src/index.ts`、`packages/dsh-adapter/src/window.ts`、`packages/dsh-adapter/tests/window.test.ts`、`packages/core/tests/runtime.test.ts`、`examples/benchmark/graph-ablation.jsonl`、`examples/benchmark/affect-ablation.jsonl`。

可运行命令：

```powershell
pnpm build
pnpm exec vitest run packages/dsh-adapter/tests/window.test.ts packages/core/tests/runtime.test.ts
pnpm benchmark:graph
pnpm benchmark:affect
```

输入例：assembly 内有 `other-plugin: keep me` 和旧 REMI window；连续装配 100 次新 window；接着空召回；再禁用/失败。预期：每次 assembly 至多一个 REMI 贡献，空召回后旧正文不可见，移除 REMI 时其他插件贡献保持，估算 token 不超过配置。预算回归覆盖 0、1、16、32、64、120 等小值。

本机扩展：同一 turn 的多 step、工具循环、取消、重试、无 direct-user 查询、故障恢复、两次压缩与重启；对照实际 provider 请求/active surface，而非只数 durable log 中保留的 snapshot events。量化门槛为当前请求有效 REMI window ≤1、旧 window 残留 0、无关插件改动 0、ACK/当前查询自召回/已删除事实进入窗口 0。

Hebbian 对照保持其他评分系数完全相同，只停止读边与强化；affect 对照保持其他系数相同，只取消 affect 提取/评分/辅助调用。不能简单把权重设 0 后再归一化，制造其他变量变化。本次已将这两个开关做成纯消融；更细的 Hebbian read-only / no-learning / edge-shuffle 实验仍待扩展。

## 本次结果与剩余边界

工作分支在 Linux / Node 24 的构建、类型检查和 13 个测试文件 / 81 项测试通过。两个新增 affect 合成用例中 full 命中率 1.0、no_affect 0.5；这是特意构造的机制用例，不是自然对话收益。原 graph fixture 中 full 和 no_hebbian 均 1.0；不能由此宣称 Hebbian 增益。

没有启动用户本机 DSH，没有进行新的真实模型调用，没有读取本机未推送代码或真实记忆数据库。Windows CI 已配置，但未把“已配置”写成“已通过”。可运行的整体框架已建立；真实线上效能、宿主版本兼容、中文实体精度、通用隐式事实更新、语义 consolidation 与 DSH 原生管理页仍需后续完善。
