# REMI v0.2.1 validation

This note separates verified behavior from product claims. Raw DSH session logs, SQLite databases, telemetry, login links, and machine-specific preset files are intentionally not committed.

## Automated project checks

The release gate is:

```powershell
pnpm install --frozen-lockfile
pnpm build
pnpm typecheck
pnpm test
```

At release preparation, build and typecheck passed and Vitest reported 7 files / 31 tests passed.

## Clean-store DSH run

The end-to-end fixture used a dedicated Agent preset, a SQLite path that did not exist before session creation, new synthetic facts, different recall phrasing, and 96 interference rounds.

Before the first model prompt, the driver checked:

```text
memories = 0
retrieval_traces = 0
memory_associations = 0
```

After the run, the audit found only the current session across those tables and zero foreign sessions. This rules out prior REMI SQLite records; it does **not** claim that a model provider's prompt/KV cache was disabled.

| Measure | Result |
| --- | ---: |
| Model turns completed | 114 |
| Interference rounds | 96 |
| Submitted user text | 176,159 characters |
| Retry events | 0 |
| Tool calls | 0 |
| Memory records | 228 (114 user, 114 model) |
| Retrieval traces | 114 (`content-aware-v1`) |
| Association edges | 13 |
| Non-empty runtime windows | 105 |
| Largest estimated REMI window | 549 / 800 tokens |

Manual `/compact` completed without a compaction error and reported 323 replaced history items (about 83,031 tokens under the host's reporting method). Before held-out recall, the active surface contained two nodes. The four held-out source statements and their eight expected field values were absent from that surface.

For each of eight recall questions, the original source memory was candidate rank 1, selected, and present in a runtime window updated after the query. The unknown-fact control returned `未约定`.

### Scoring disclosure

The strict JSON scorer produced:

- before compaction: 3 / 8 fields;
- after compaction: 2 / 8 fields.

The unchanged model answers contained all 16 expected fact values on human review. The mismatch came from output representation: aliases such as `包装用色` and `验收口令`, a `模式` suffix, and a schedule split into period and time fields. The scorer was not relaxed after seeing the answers, and no prompts were resubmitted. Therefore 8/8 + 8/8 is a content review, not an automatic benchmark score.

Future benchmark runs must freeze an output schema or a representation-normalizing scorer before model execution.

## Reproduction tools

The public scripts do not contain credentials or provider configuration:

```powershell
# Generate the V3 fixture without model calls.
node packages/benchmark/scripts/prepare-long-dialogue.mjs .dsh-memory/clean-v3 --fresh-v3

# Execute only against a local DSH endpoint. Supply the one-time local login URL
# and the packaged root used solely to resolve the WebSocket client.
$env:REMI_DSH_LOGIN_URL = '<local DSH login URL>'
$env:REMI_DSH_INSTALL = '<DSH resources/app.asar.unpacked path>'
node packages/benchmark/scripts/run-dsh-long-dialogue.mjs .dsh-memory/clean-v3 --preset=<dedicated-preset-id> --clean-db=.dsh-memory/clean-store/memory.sqlite

# Read-only audit; this never contacts a model.
node packages/benchmark/scripts/audit-dsh-full-test.mjs .dsh-memory/clean-v3/run-<timestamp> .dsh-memory/clean-store/memory.sqlite
```

The execution driver stops on the first failed model turn or observed DSH retry event and never resubmits a prompt. Provider-owned cancellation is still subject to a race, so raw provider logs remain the source of truth for attempted requests.

## What this does not prove

- It is one synthetic Chinese fixture, not statistical evidence of general quality.
- There is no no-plugin model baseline, compaction-only baseline, Hebbian ablation, or affect-model ablation yet.
- Provider usage counters are not billing estimates, and cost reduction has not been established.
- Restart recovery, repeated compaction, current-truth/superseded facts, deletion, cross-session scope, and real coding-task continuity remain Alpha work.
- DSH Desktop compatibility is verified only for the recorded host backend, not every past or future Harness build.
