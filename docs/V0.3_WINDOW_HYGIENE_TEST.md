# v0.3 transparent-window hygiene DSH validation

This note records the bounded live validation for `window-hygiene-v2`. It is separate from the current-truth lifecycle gate because it tests prompt-window admission rather than fact replacement.

## Configuration and boundary

The run used DSH Desktop 2.0.6 with the existing v0.3 alpha preset, a dedicated SQLite sidecar, telemetry enabled, and a new DSH session for each attempt. The loaded compatibility baseline reported `deepseek-ai/deepseek-harness@c291e796` with packages `0.1.5-rc.2`; the Desktop compaction backend reported `0.1.2-rc.1`.

The protocol used short English facts with explicit ASCII entity names. It did not test CJK-only entity isolation, long-duration recall, cross-session retrieval, post-compaction recall, or provider-independent answer quality.

## Protocol

The complete protocol wrote:

1. a current fact with a leading test/output instruction;
2. a sibling entity with a different value;
3. a conditional future change;
4. the current fact again with a trailing output instruction;
5. a current-value query for the first entity;
6. a current-value query for the sibling entity;
7. an explicit future-plan query.

The final minimal gate repeated only steps 1, 4, and 5 with a fresh entity after the last deduplication fix.

## Live findings and fixes

The first attempt produced correct model answers but did not pass the mechanism gate. Telemetry showed that DSH-rendered acknowledgement wrappers were classified as statements, and an explicitly requested conditional record remained below the minimum score. Commit `f1aec54` added wrapped-ACK recognition and restored full conditional utility only when the query explicitly requests plans or possible later changes.

The second attempt confirmed wrapped acknowledgements as `low-utility`, sibling entities as `focus-mismatch`, ordinary future records as `conditional`, and an explicitly requested future record as `selected` with `utilityFactor = 1`. It also exposed that deduplication depended on the literal word `test`; a `retest` wrapper allowed both copies of the same fact into the window. Commit `e28db4c` replaced that title-specific rule with general output-directive clause recognition.

After rebuilding and restarting DSH, the third attempt passed the final minimal gate:

| Check | Result | Telemetry evidence |
| --- | --- | --- |
| Model-visible current value | Pass | The model returned the single expected value. |
| Duplicate admission | Pass | One fact candidate was `selected`; the semantically identical instruction-wrapped candidate was `redundant`. |
| Acknowledgement exclusion | Pass | Both acknowledgement records were `low-utility` with `contentKind: acknowledgement`. |
| Window size | Pass | `candidateCount: 4`, `selectedCount: 1`, `estimatedTokens: 82`. |
| Graph isolation | Pass | `reinforcedEdges: 0` for the one-item final window. |
| Scoring version | Pass | The trace reported `window-hygiene-v2`. |

The earlier complete attempt also passed the conditional and sibling-entity checks after `f1aec54`: the explicit future query selected the conditional record with full utility, while the sibling fact was rejected by `focus-mismatch`.

## Interpretation

This validates the implemented admission mechanics against the tested DSH event ordering and model-output wrappers. It does not establish a general improvement in answer quality or production cost. The model answers were checked, but telemetry decisions—not surface correctness alone—determined the result.

The SQLite sidecar contains raw conversation text and remains sensitive local data. The public evidence above intentionally omits local absolute paths, session identifiers, raw telemetry files, and access tokens.
